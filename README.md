# 나의 책장 (어드민 + 사이트)

읽은 책을 등록하면 표지가 꽂힌 책장 사이트가 만들어지는 템플릿이다. 버킷리스트 클럽 7회차 실습용으로, 클럽장의 책장(https://byminseok.com/shelf-portrait/)에서 구조만 가져와 가볍게 다시 만들었다.

폴더는 두 쪽으로 나뉜다.

| 쪽 | 폴더 | 어디서 열리나 | 하는 일 |
| --- | --- | --- | --- |
| 어드민 | `admin/` | 내 컴퓨터에서만 | 책을 찾고, 꽂고, 고치고, 게시한다 |
| 사이트 | `docs/` | 웹 (GitHub Pages) | `shelf.json` 하나를 읽어서 책장을 그린다 |

## 켜기

`run.command`(Windows는 `run.bat`)를 더블클릭한다. 어드민이 브라우저에 열린다. 또는 터미널에서

```bash
python3 admin/server.py      # http://127.0.0.1:8799
```

어드민 오른쪽 위의 "사이트 미리보기"를 누르면 웹에 올라갈 화면을 내 컴퓨터에서 먼저 볼 수 있다. 끌 때는 터미널 창에서 Ctrl+C. 처음에는 샘플 책 여섯 권이 꽂혀 있고, 어드민의 "샘플 지우기"로 한 번에 뺄 수 있다.

## YES24 키 넣기

책 검색에는 YES24 API 키가 필요하다. https://developers.yes24.com/ 에서 YES24에 가입하고 로그인하면 바로 받을 수 있다.

1. 이 폴더의 `.env.example`을 복사해서 이름을 `.env`로 바꾼다
2. `.env` 안의 `여기에-키를-붙여-넣으세요` 자리에 키를 붙여 넣는다
3. 어드민을 껐다 켠다

`.env`는 비밀번호와 같다. `.gitignore`에 들어 있어서 GitHub에 올라가지 않는다. 키 없이도 어드민의 "직접 적기"로 책을 꽂을 수 있고, 그 책은 표지 대신 제목 카드로 나간다.

## 책을 꽂고 웹에 올리기까지

```
① 찾기 → ② 꽂기 → ③ 사이트 미리보기로 확인 → ④ 게시 → ⑤ GitHub에 올리기(push)
```

어드민에서 꽂고 고친 것은 `data/books.json`에 저장된다. **게시**를 눌러야 사이트가 읽는 `docs/shelf.json`이 새로 써진다. 고치는 중인 것이 바로 웹에 나가지 않게 두 걸음으로 나눴다. 게시한 다음 push 하면 1~2분 뒤 웹에 반영된다.

## 웹에 처음 올리기

처음 한 번만 하면 된다. Claude Code(코덱스)에게 이렇게 말한다.

```
이 폴더를 GitHub에 공개 저장소로 올리고 GitHub Pages로 웹에 공개하고 싶어.
저장소 이름은 [my-shelf]로 해줘. Pages는 main 브랜치의 docs 폴더로 켜줘.
올리기 전에 .env 파일이 .gitignore에 있어서 올라가지 않는지 먼저 확인해줘.
다 되면 사이트 주소를 알려줘.
```

주소는 `https://[내 GitHub 아이디].github.io/[저장소 이름]/` 이 된다. 처음 켤 때는 몇 분 걸릴 수 있다.

**저장소는 공개다.** `docs/`만이 아니라 `data/books.json`, 어드민 코드까지 저장소에서 누구나 볼 수 있다. 남에게 보이기 싫은 메모는 적지 않는다. `.env`만 빠진다.

## 그다음부터

책을 꽂고 게시한 다음, Claude에게 "책장을 게시했어. 바뀐 파일을 커밋하고 GitHub에 올려줘"라고 하면 된다. 직접 한다면

```bash
git add .
git commit -m "책장: 새 책"
git push
```

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `admin/server.py` | 어드민 서버. YES24 검색, 책 저장, 게시. 파이썬 표준 라이브러리만 써서 설치할 것이 없다 |
| `admin/admin.html` | 어드민 화면 |
| `data/books.json` | 내 독서 기록 원본. 어드민이 쓴다 |
| `docs/index.html` | 사이트 화면. 디자인은 마음대로 바꿔도 된다. 색과 글꼴만 살짝 바꿀 때는 맨 위 `:root`의 값을 고치면 전체에 반영된다 |
| `docs/shelf.json` | 사이트가 읽는 파일. 게시 버튼이 만든다. 손으로 고치지 않는다 |
| `.env` | YES24 API 키. GitHub에 올라가지 않는다 |
| `만든-과정.md` | 클럽장 책장을 만든 과정 |

## 내 것으로 바꾸기

**디자인은 완전히 내 마음대로 바꿔도 된다.** 지금 화면은 출발점일 뿐이다. 색, 글꼴, 배치, 책이 놓이는 방식까지 전부 바꿔도 어드민과 게시는 그대로 돌아간다. 사이트가 `shelf.json`만 읽기 때문이다. 마음에 드는 사이트를 녹화해서 보여 주거나, 원하는 느낌을 말로 설명하면 된다.

Claude에게 이 README와 `만든-과정.md`를 읽히고 바꾸고 싶은 것을 말하면 된다. 예를 들면

- "사이트를 연도별 말고 분류별로 묶어 줘"
- "책을 누르면 열리는 상세 창에 '다시 읽고 싶은 책' 표시를 넣어 줘. 어드민 입력 칸도 같이"
- "[녹화 파일]의 분위기로 사이트 디자인을 바꿔 줘. 어드민은 그대로 두고 docs/index.html만"

책이 아닌 것으로도 바꿀 수 있다. 책 전용인 곳은 YES24에서 정보를 받아오는 부분(`server.py`의 ② YES24)뿐이고, 기록 저장, 어드민 입력 화면, 게시, 사이트는 그대로 쓸 수 있다.

```
이 책장 구조(어드민 + 사이트, 게시 버튼)는 그대로 두고 책 대신 [내 식물 / 달리기 기록 / ...]을 기록하는 사이트로 바꾸고 싶어.
YES24 검색 대신 [사진 올리기 / 직접 입력]으로 바꿔 줘. 한 건마다 남길 칸은 [이름, 들여온 날, 메모]야.
먼저 어느 파일의 어디를 바꿀지 알려 주고, 내가 좋다고 하면 고쳐 줘.
```

## 지켜야 할 것

- **YES24 출처 표시.** YES24 API는 화면에 출처를 표시하고 상품 페이지 링크를 두는 조건으로 쓴다. 사이트 아래쪽의 "도서 정보와 표지 제공 YES24"와 책 상세의 "YES24에서 보기"가 그 조건이다. 지우지 않는다
- **내 책만 저장한다.** 서점 전체 정보를 긁어 쌓는 것은 이용 조건 위반이다. 검색은 내가 읽은 책을 찾을 때만 쓴다
